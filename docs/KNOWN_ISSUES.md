# 已知问题与后续建议

## 本版已修复

超长历史引发 422、角色保存失败后仍重置历史、首次设置覆盖旧历史、请求总耗时失控，以及名字空白校验不一致。详见 [更新日志](../CHANGELOG.md)。

## 仍存在的限制

| 问题 | 触发场景与影响 | 当前应对 / 后续方向 |
| --- | --- | --- |
| 多标签页覆盖历史 | 多个页面各自持有历史快照，后保存者可能覆盖另一页的新消息 | 暂时使用一个标签页；后续增加跨页同步与写入冲突检测 |
| 本地存储容量有限 | 长时间聊天可能超出 localStorage 配额；程序会提示，但刷新可能丢失未保存部分 | 及时复制需要的内容；后续提供导出、导入与 IndexedDB 存储 |
| 历史数量上限 | 超过 40 个会话会裁掉较旧会话 | 后续增加归档或明确的容量提示 |
| 停止不等于停止计费 | 浏览器取消请求不保证上游立即停止生成 | 后端总时限限制等待；后续实现客户端断开到上游任务的取消传播 |
| 无鉴权与限流 | 将服务暴露公网后，其他人可能使用你的模型额度 | 当前只适合本地单用户；公网部署前补齐认证、限流及额度控制 |
| 上下文不是长期记忆 | 仅携带最近 30 条及约 90,000 字符；单条历史最多发送前 20,000 个 Unicode 字符 | UI 历史仍完整，但模型可能忘记更早细节；后续考虑摘要与明确的记忆设置 |
| 人设依赖模型遵循 | 性格提示词及角色边界不能保证任何模型都完全遵循 | 选择合适的兼容服务，补充实际对话评测 |
| 健康状态不是模型连通性 | `/api/health` 的 `online` 只代表已配置凭据 | 真正聊天才能验证模型权限、地址和协议是否可用 |

## 回归测试

```bash
uv sync --frozen
uv run --frozen python -m unittest discover -s tests -v
node --test tests/frontend.test.cjs
```

Node 仅用于前端逻辑测试，不是运行页面所必需。测试不读取生产凭据、不请求真实模型。尚未覆盖真实模型响应质量、跨浏览器兼容性及多用户负载。
